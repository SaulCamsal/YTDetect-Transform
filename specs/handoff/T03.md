## Resumen de cambios
- Se crearon los contratos formales para SQS y WebSub:
  - `specs/contracts/C3-sqs-messages.md`: Estructura del mensaje `DownloadJobMessage` para la cola `youtube-download-queue`.
  - `specs/contracts/C4-websub-atom.md`: Protocolo PubSubHubbub (suscripción, GET challenge verification, POST Atom XML y validación HMAC).
- Se creó la especificación de tarea `specs/tasks/T03-video-discovery-and-sqs.md`.
- Se definió el DTO compartido inmutable `DownloadJobMessage` en `yt-common/src/main/java/com/monitorlatino/ytdetect/common/dto/DownloadJobMessage.java`.
- Se agregó la dependencia `spring-cloud-aws-starter-sqs` a `yt-api/pom.xml`.
- Se configuraron los parámetros de WebSub, Polling, Live Stream Watcher y SQS en `yt-api/src/main/resources/application.yml`.
- Se implementó `YoutubeDownloadQueueService` utilizando `SqsTemplate` de Spring Cloud AWS para enviar mensajes a `youtube-download-queue`.
- Se implementó el subsistema de WebSub:
  - `HmacSignatureValidator`: Verificación en tiempo constante contra ataques de temporización para firmas HMAC SHA-1 y SHA-256 (`X-Hub-Signature`).
  - `AtomFeedParser`: Parser XML seguro con mitigación XXE para extraer elementos del feed Atom de YouTube (`videoId`, `channelId`, `title`, `publishedAt`).
  - `WebSubService`: Cliente HTTP para registrar suscripciones y desuscripciones en el hub de Google (`https://pubsubhubbub.appspot.com/`) y renovación automática de leases.
  - `WebSubCallbackController`: 
    - `GET /api/v1/youtube/websub/callback`: Verificación de challenge del hub, actualizando `websub_status` (`VERIFIED`, `EXPIRED`) y `websub_lease_expires_at`.
    - `POST /api/v1/youtube/websub/callback`: Validación criptográfica HMAC y despacho de videos detectados a `VideoDiscoveryService`.
- Se implementó `VideoDiscoveryService`:
  - Optimización de cuota de YouTube API consultando `existsByVideoId` previo a llamadas de red.
  - Consulta en lote de metadatos con `videos.list` (hasta 50 por petición).
  - Regla de duración máxima de 10 horas (36,000s): descarta videos mayores marcándolos como `SKIPPED` con código `DURATION_LIMIT_EXCEEDED`.
  - Detección de transmisiones en vivo (`live` o `upcoming`): clasificados como `WAITING_LIVE`.
  - Videos regulares completados: guardados con estado `QUEUED_DOWNLOAD` y enviados de inmediato a SQS.
  - Idempotencia y control de concurrencia ante `DataIntegrityViolationException`.
- Se implementó `YoutubePollingService`:
  - Tarea programada `@Scheduled` con ShedLock (`@SchedulerLock(name = "youtube_polling")`) que monitorea las listas de reproducción `uploadsPlaylistId` de canales activos como respaldo ante fallos de WebSub.
- Se implementó `LiveStreamWatcher`:
  - Tarea programada `@Scheduled` con ShedLock (`@SchedulerLock(name = "youtube_live_stream_watcher")`) que re-evalúa videos en estado `WAITING_LIVE`. Al finalizar la transmisión, valida que la duración no exceda 10 horas y los encola a SQS en `QUEUED_DOWNLOAD`.

## Decisiones tomadas
- Se utilizó el enum `WebSubStatus` existente (`PENDING`, `VERIFIED`, `EXPIRED`) configurado en el esquema de la base de datos, mapeando la desuscripción o rechazo a `EXPIRED`.
- En `VideoDiscoveryService`, la duración ISO 8601 de YouTube (`PT#H#M#S`) se procesa con `java.time.Duration.parse`, permitiendo validación precisa de los 36,000 segundos (10 horas).
- Para la validación HMAC, se utilizó `java.security.MessageDigest.isEqual` para asegurar comparación en tiempo constante y evitar vulnerabilidades de timing attacks.
- Los locks de ShedLock se configuraron con nombres independientes (`youtube_polling` y `youtube_live_stream_watcher`) para garantizar que la ejecución distribuida sea atómica entre múltiples instancias de `yt-api`.
