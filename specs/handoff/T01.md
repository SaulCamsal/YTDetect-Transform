# Handoff Tarea T01 - Configuración Inicial del Módulo yt-common

**Agente:** Gemini 3.8 Flash (T01 Implementation Agent)
**Estado:** COMPLETED
**Rama:** `feat/T01-common-module-setup`

## Resumen de cambios
- Se creó el archivo `pom.xml` raíz multi-módulo configurando Spring Boot 4.1.1, Java 21, Spring Cloud AWS 4.2.0 y el BOM de ShedLock 6.3.0.
- Se generó el wrapper de Maven (`mvnw`, `mvnw.cmd`, `.mvn/wrapper/`).
- Se creó el módulo `yt-common` con su `pom.xml` incluyendo `spring-boot-starter-data-jpa`, `mssql-jdbc` y dependencias de prueba (`spring-boot-starter-data-jpa-test`, `h2`).
- Se crearon los enums de dominio en `com.monitorlatino.ytdetect.common.domain.enums`:
  - `ChannelOrigin`
  - `WebSubStatus`
  - `LiveStatus`
  - `VideoStatus`
  - `DiscoveredVia`
  - `TranscriptionStatus`
- Se crearon las entidades JPA en `com.monitorlatino.ytdetect.common.domain.entity` mapeando el schema `youtube` de SQL Server conforme al contrato C1:
  - `YoutubeChannel` (con `@Version Long version`, control de cursor y estado de WebSub).
  - `YoutubeVideo` (con relación `@ManyToOne` hacia `YoutubeChannel`, `@Version Long version`).
  - `YoutubeAudioChunk` (con relación `@ManyToOne` hacia `YoutubeVideo`, restricciones únicas por video e índice).
- Se crearon los repositorios JPA en `com.monitorlatino.ytdetect.common.domain.repository`:
  - `YoutubeChannelRepository` (incluye bloqueo pesimista `findByChannelIdForUpdate` para la asignación concurrente de slots virtuales).
  - `YoutubeVideoRepository` (búsquedas por `videoId`, estados, canal).
  - `YoutubeAudioChunkRepository` (ordenamiento por `chunkIndex`, búsquedas por `transcriptionJobId` y estados).
- Se implementaron pruebas unitarias de slice JPA (`YoutubeRepositoryTest`) verificando persistencia y consultas con éxito total (`BUILD SUCCESS`, 3 pruebas pasadas).

## Decisiones tomadas
- Se utilizó Spring Boot 4.1.1 y el starter modular `spring-boot-starter-data-jpa-test` con la anotación `org.springframework.boot.data.jpa.test.autoconfigure.DataJpaTest` propia de Spring Boot 4.
- Para las fechas UTC (`created_at`, `updated_at`, `published_at`, `websub_lease_expires_at`, `last_check_at`) se utilizó `Instant`, mientras que para fechas locales del canal (`timeline_cursor`, `virtual_start`, `aired_at_local`) se utilizó `LocalDateTime`.
- La tabla `shedlock` no requiere entidad JPA ya que la biblioteca `shedlock-provider-jdbc-template` opera directamente sobre la tabla mediante JDBC.

## Bloqueos / Contract Issues
Ninguno. El esquema `youtube` y las entidades mapean al 100% de manera consistente.
